# QQ 博客 Image2

用户已指定本入口用博客同款 `gpt-image-2`。使用当前已加载的 `qq_generate_image` 工具提交画面要求；凭据、后台生成和图片发送均由接入服务处理。普通用户只需说想画什么，不需要压缩命令、内部文件名或服务器路径。

## 一句话完成生图

1. 根据当前明确要求和已提供的图片理解画面。续做时保留本会话已确认的角色、数量、颜色及修正；不要把无关闲聊角色当成群成员。群成员列表不会自动传入，只依据已提供的名单和截图，不能声称看过用户客户端。
2. 调用实际 `qq_generate_image`，`prompt` 为完整画面描述，`aspectRatio` 选 `1:1`、`16:9`、`4:3`、`3:2`、`2:3`、`3:4`、`9:16` 或 `21:9`。默认 `1:1`；涉及圆形头像时把主体与文字留在安全区。直接把描述传给工具，不额外写提示词文件、裁切截图、执行 CLI 或查凭据。
3. 工具立即返回已登记的进度。简短自然回应“正在画，完成后直接发到这里”；排队时据实说排队。后台会生成并发送，模型本轮结束或超时不会取消该任务。

同一条用户消息只会提交一单。不要重复调用、不轮询等文件、不再自己发图，也不为该任务输出 `qqimg` 标签；服务负责这一张图的最终交付。不要无请求添加圆角、遮罩或反复检查像素。工具登记不等于图片已发送，只有已确认的实际回执才算送达。

## 查询和恢复

用户自然追问“图呢”“好了吗”“再发一下”时，由服务的任务记录查进度或重投同一张现有图片。需要工具查询时用 `qq_image_status`；不要猜文件名或搜目录里的旧 PNG。发送失败不等于生成失败，不能因此重新生图。结果未知时据实说明，不自动重复扣费尝试。

用户只讨论配置、问是否支持或发表情时，不提交生图。工具不可用时说明当前实际不可用，不退回旧 CLI 路径自行绕开任务管理。

当前生成器输出 RGB PNG，支持文生图；已有截图可以先理解为文字提示。透明背景及原图编辑需要已验证的独立接口，不能把重绘称作原图编辑。不要向用户暴露任务 ID、内部路径、API 密钥或维护命令。
