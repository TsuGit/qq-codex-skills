# QQ 定时提醒（Codex 适配）

使用本轮实际提供的 `qq_status` 与 `qq_reminder`。调度器会持久保存任务，到期向当前对话发送所存的提醒文字；登记后不需要保持模型回合运行。只有工具确认注册成功，才能说“已安排”。

## 安排时间

先确认用户要求的内容与时间。明确的相对时间直接计算；缺少时间或“晚点”等含义不清时再问。默认向用户解释的时区为 `Asia/Shanghai`，用户明确指定其他时区则按该时区处理。

- “五分钟后提醒喝水”：先调用 `qq_status({})` 读取真实 `now`，加五分钟得到带时区的未来 ISO 时间，再调用 `qq_reminder`，参数为 `{"action":"add","text":"该喝水了。","schedule":{"type":"once","at":"计算后的ISO时间"}}`。一次性提醒不能误建成循环。
- “每小时提醒喝水”：`{"action":"add","text":"该喝水了。","schedule":{"type":"interval","seconds":3600}}`。
- “每天早八点提醒打卡”：`{"action":"add","text":"该打卡了。","schedule":{"type":"daily","time":"08:00","timeZone":"Asia/Shanghai"}}`。

间隔只支持 60～31536000 秒。当前不支持任意 cron、工作日或每周规则；不能用每天提醒冒充工作日提醒，也不要自行展开大量任务。向用户说明具体限制，并询问是否改为支持的时间安排。到期发送的是已存文本，不承诺届时执行命令、重新调用模型或生成实时信息。

## 查询和管理

用 `{"action":"list"}` 取得当前会话的真实任务。用户按名称取消或暂停时先匹配这份列表；多个任务含义相近时再确认具体哪一个，不批量猜测。

管理参数只含 `action` 与真实 `id`：`remove` 删除，`pause` 暂停，`resume` 恢复。没有 update 接口；修改时间需要先明确目标和新安排，再处理旧任务并新增，分别确认两步结果。操作失败就如实说明，不能将旧提醒已取消说成新提醒已安排。

目标由入口绑定，不填写收件人、群号或其他账号。不要运行 OpenClaw 的 cron 命令、拼造平台请求或另起进程模拟调度。

## 判断结果

- `registered:true` 且存在真实 `job.id`：已持久登记；`deliveryVerified:false` 表示尚未验证投递。自然回复提醒内容与时间即可，不向用户堆内部 ID。
- `list` 中的 `deliveries`、`lastReceipt`、`lastError` 才能证明实际投递或失败。QQ 主动消息权限会影响到期发送；登记成功不能说成已发到 QQ。
- 结果未知时先查询已有任务，禁止直接重复新增或恢复，避免双重提醒。一次性任务完成后可能保留 completed/paused 记录，不能将它当成没执行过。
- 隔离诊断只可登记 `paused:true` 的测试提醒，始终禁止向 QQ 投递；测试完只删除本轮创建的任务。

本技能依据腾讯 QQBot 的提醒规则适配；工具、调度及会话接口已替换为当前 Codex broker。许可证见随包 LICENSE。
